# Sky Target Finder (Space-Track tool)

A smart-telescope-style target finder inside the Space-Track tool, at
**`/space-track/sky`** ("Sky Target Finder" in the sidebar, directly under
Space-Track Control). It reproduces the target-search and sky-atlas workflow of
consumer smart-telescope apps for this program's observers:

- **Search** stars, Messier and Caldwell objects, the Sun, Moon and planets, and
  Space-Track satellites by designation, common name or alias. Matching is
  case- and accent-insensitive; "East" finds *C 33 (East Veil Nebula)* and
  *Theta Cassiopeiae (Marfak)* through its alias *Marfak-East*.
- **Recommend** tonight's best-placed Messier/Caldwell objects, planets and Moon
  for the observer's nautical-dark window (Sun below −12°).
- **Favorites**, kept in the browser's local storage only.
- Each row shows the live altitude (`∠ 75°`) when the target is up, or its
  rise–set window in local time when it is down.
- **Sky chart**: a horizon-oriented atlas centred on the target, with the
  camera field-of-view rectangle (1–12°), stars to magnitude 7.5, constellation
  figures, star and deep-sky labels, planets, satellites, the horizon line, a
  compass rose showing true N/E/S/W, and the local time. A heuristic imaging
  filter hint (`Duo-Band` for line-emitting nebulae, `Broadband` for galaxies
  and clusters) is shown on the target card.
- **Copy target coordinates** copies J2000 RA/Dec, the current altitude and
  azimuth, the observer and the UTC time as text. It does not control any
  telescope.

The observer defaults to San Juan, Puerto Rico (18.4655 N, 66.1057 W, 10 m) and
can be changed on the page, as can the observation time (default: now).

## Boundary

Read-only, like the rest of the Space-Track tool. The browser never calls an
upstream service. Star and deep-sky positions come from a vendored catalog,
Sun/Moon/planet positions are computed locally, and satellites are propagated
only from the Space-Track `space_objects` materialization that has already been
frozen into the local store (`SKYWATCHER_SPACE_TRACK_ROOT`, default
`data/spacetrack`). Until a Space-Track collection is materialized, the
satellite layer reports `NOT_MATERIALIZED` and lists nothing.

## API

All three are `GET`, read-only and return schema-versioned JSON. Shared query
parameters: `lat` (−90..90, default 18.4655), `lon` (−180..180, default
−66.1057), `elev_m` (−500..10000, default 10) and `at` (ISO-8601; `Z`, an offset,
or naive meaning UTC; years 1800–2200; default now). Out-of-range values return 422.
A search propagates only the satellites whose names or ids match, and non-satellite
kinds propagate none.

| Endpoint | Purpose | Extra parameters |
|---|---|---|
| `/api/space-track/sky/targets` | Search, or list what is above the horizon when `q` is empty (brightest first). Includes the satellite-layer state. | `q`, `kind` (`all`, `star`, `messier`, `caldwell`, `solar_system`, `satellite`), `limit` (1–200) |
| `/api/space-track/sky/recommend` | Up to 20 targets ranked by best altitude in tonight's dark window and brightness. | — |
| `/api/space-track/sky/chart` | Chart layers around one target, as apparent altitude/azimuth; the browser projects them (gnomonic). Unknown target: 404. | `target` (an id from `targets`), `fov_deg` (0.5–60, default 6), `radius_deg` (default max(2×FOV, 10°)) |

Implementation: `server/backend/spacetrack_router.py` (HTTP) over
`src/skywatcher/core/sky/` (catalog search, ephemeris, SGP4 satellites, chart
layers, payloads). Frontend: `frontend/src/pages/SkyTargetFinder.jsx`,
`frontend/src/components/skywatcher/SkyChart.jsx`,
`frontend/src/lib/skyProjection.js` and `frontend/src/lib/skyFavorites.js`.
Backend dependencies (`server/backend/requirements.txt`): `astronomy-engine`
2.1.19 and `sgp4` 2.27, both MIT. If astronomy-engine is missing the endpoints
return 503 `DEPENDENCY_MISSING`; if only sgp4 is missing, satellites report
`DEPENDENCY_MISSING` and everything else works.

## Data and licensing

The catalog lives in `data/reference/sky/` and is generated by
`scripts/build_sky_catalog.py` from inputs pinned by URL and sha256 in
`data/reference/sky/sources.lock.json`: d3-celestial 0.7.35 (BSD-3-Clause),
OpenNGC v20260501 and the Stellarium v26.3 "modern" sky culture (both
CC BY-SA 4.0), plus Caldwell names frozen from a pinned Wikipedia revision. The
generated catalog files are therefore **CC BY-SA 4.0**; this applies to those
data files only, not to the repository's code. See
`data/reference/sky/ATTRIBUTION.md` and `data/reference/sky/README.md`.

```bash
python3 scripts/build_sky_catalog.py --fetch   # download pinned inputs to a local cache
python3 scripts/build_sky_catalog.py           # regenerate from the cache (offline, deterministic)
python3 scripts/build_sky_catalog.py --verify  # validate the committed outputs (offline)
```

## Accuracy and limits

- **Stars and deep-sky objects**: astronomy-engine precession/nutation and
  sidereal time (documented ±1 arcminute). Tested against USNO altitudes and
  azimuths for San Juan to 0.03°. Catalog positions are J2000 and are not
  propagated for proper motion; by 2026 that shifts most stars by well under
  0.02° and the fastest catalog star (61 Cygni) by about 0.04°.
- **Visibility windows** for fixed objects use a closed-form hour-angle
  solution and agree with astronomy-engine's search to a few seconds. Sunrise,
  sunset and civil twilight match USNO to within 2–3 minutes; the Moon's
  position includes topocentric parallax and matches USNO to 0.05°.
- **Satellites**: SGP4 over the frozen element sets. The pipeline matches the
  Vallado verification vectors and a published ISS pass to 0.02°. Accuracy is
  limited by element age, roughly 1–3 km per day. Elements more than 30 days from
  epoch, decayed objects, non-SGP4 ephemeris types and rows that fail SGP4 are
  skipped, each with a stated reason. The sunlit flag uses a cylindrical
  Earth-shadow approximation. No pass prediction: a satellite's visibility is
  only up or down at the requested time.
- **Altitudes** are apparent (standard atmospheric refraction). The **filter
  hint** is a heuristic from object type, not a measurement.
